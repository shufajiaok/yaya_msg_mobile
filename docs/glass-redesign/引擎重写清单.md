# 引擎重写清单（Phase 2 · GlassKit → RN 原生引擎）

> 依据：朋友深度阅读报告 v2.7.7（2026-11-07）+ 用户指令「马上开始重写引擎」
> 基线：D:/glass/yaya_msg_mobile（v2.7.5 / e324df4 / RN 0.81.5 / Paper / minSdk 26）
> 日期：2026-11-07

## 〇、路线裁决（主理人已定，用户可否决）

**抛掉 Compose，重写为纯 Kotlin 原生引擎。**

| 对比 | 原 GlassKit（Compose） | 新引擎（纯 Kotlin View） |
| --- | --- | --- |
| 背板采集 | `layerBackdrop`（只采 Compose 内容） | 直接 `View.draw(canvas)` 采集 RN 原生子树 |
| RN 内容折射 | ❌ 采不到 | ✅ 可以 |
| 新增依赖 | backdrop 2.0.1 + shapes 1.2.1（断网装不了） | **零依赖**（全平台 API） |
| 桥接 | 需 Compose 构建特性 + LifecycleOwner 注入 | `SimpleViewManager`（LiveExoViewManager 同款先例） |
| 视频画面 | 采不到 SurfaceView | 采集子树方案同样采不到（记录为已知限制） |

理由：① 朋友报告 §6.9 铁律「blurTarget 只包背景层」+ 现有 `BlurTarget.tsx` 证明「采指定背景子树」这条路在本 App 已验证可行；② 引擎差异化价值在折射/色散透镜（expo-blur 没有），不在模糊本身；③ 断网环境零依赖是唯一可落地路径。

## 一、架构契约

```
JS 层
  <GlassKitBackdrop ref>          ← 背景容器（内容层，包住背景图/渐变）
  <GlassKitView backdropTag=...>  ← 玻璃面板（功能层叶子视图，无子节点）

原生层（com.yk1z.yayamsg.glasskit，Kotlin，全新增）
  GlassKitBackdropManager   ← 背景容器 ViewManager（空 FrameLayout，注册表 key）
  GlassKitManager           ← 玻璃面板 ViewManager（props → 视图）
  GlassKitView              ← 渲染核心：捕获 → 模糊 → 透镜 → 着色
  GlassCaptureEngine        ← 子树捕获（平移对齐玻璃区域）
  GlassLensShader           ← AGSL 透镜（折射位移 + 色散），API 33+
  GlassKitPackage           ← ReactPackage
```

## 二、渲染管线（GlassKitView）

1. **捕获**：注册表按 `backdropTag` 找到背景视图 → `view.draw(canvas)`，canvas 预平移
   `-(glassInBackdropX, glassInBackdropY)`，只采玻璃覆盖区域（省内存）。
2. **模糊**（API 31+）：`RenderEffect.createBlurEffect(blurDp * blurScale)` 挂 RenderNode；
   API 26–30 降级：降采样 1/4 + 双线性放大（近似模糊），复用 H2 单档 `canBlur()` 语义。
3. **透镜**（API 33+）：AGSL `RuntimeShader`，输入模糊后位图 shader：
   - 边缘折射位移：`uv += normal * refractionPx * edgeFactor`（edgeFactor 由到圆角矩形边界距离决定）
   - 色散：R/G/B 三通道位移量错开 `dispersionPx`（对应引擎 `chromaticAberration`）
   - API < 33：跳过透镜（`canLens()` = false，复用 H2 双档语义）。
4. **着色**：`tint.copy(alpha = min(tintAlpha * tintScale, 0.12))` —— H1 上界原样生效。
5. **压暗**：`#000 @ glassDimming(0.35)`（clear+亮底档，独立于 tint）。
6. **高光**：圆角矩形描边 `1dp #FFF @0.14`。
7. **裁剪**：`Path.addRoundRect(cornerRadius)` clip。
8. **降级**：`degrade(reason)` 六类镜像 glass.ts（api<31 / lensUnavailable / reduceTransparency /
   reduceMotion / lowEnd / budget），原生侧只处理 api 两档；其余四类由 JS 门控不挂载。

## 四、明确不动（越界即撤回）

- **页面零接线**：所有 Screen / GlassSurface.tsx / AppTabBar 不引用新引擎（本批只交付能力，不做 UI）。
- expo-blur 及其 2 处 BlurView 用法不动；`GlassCard.tsx` 等现有组件不动。
- `build.gradle` / `gradle.properties` / 依赖清单：**零新增依赖、零构建特性改动**（无 Compose）。
- 现有 `LiveExoViewManager` 等全部原生文件不动（MainApplication.kt 仅 +1 行注册）。
- glass.ts 既有契约不动（引擎参数语义与它对齐，不反向修改）。

## 五、验证方式与已知局限

- 可做：`grep` 断言、逐文件核对、AGSL 语法静态自查、git diff 范围核验、守卫脚本不回归。
- **不可做（如实声明）**：无 JDK/SDK → 无法编译 `assembleDebug`；无真机 → 无法验证渲染效果。
  编译验证需朋友 CI（ci-build 分支）或装好工具链后补跑。
- 已知限制（登记）：采不到 SurfaceView 视频帧（直播画面上玻璃仍是膜层+压暗）；PixelCopy
  方案（可采视频）登记为未来增强，本批不做。
